# 検証と運用

## 試験要件

単体試験と結合試験を用意する。実際の本番証明書、秘密鍵、資格情報は使わず、一時ディレクトリと生成したテストCAを用いる。セキュリティに関わる各動作に試験を追加する。

| ID | 対象 | 受け入れ条件 |
| --- | --- | --- |
| T01 | 設定 | 未知・重複キー、型不正、空の必須値、重複ID、危険なパス・権限を拒否 |
| T02 | TLS | 正しいプライベートCAで成功し、未知CA・ホスト名不一致・期限切れで失敗 |
| T03 | 認証 | 欠落・不正・無効トークンと未知IDを拒否し、ログに資格情報を残さない |
| T04 | IP | IP/CIDR境界、IPv4/IPv6、mapped IPv6を検証し、転送ヘッダーで回避できない |
| T05 | 認可 | 許可されていない証明書を一覧・metadata・downloadから取得できない。DNS台帳モードでは同名レコードのIPと例外ホストのIPを許可し、未知の例外ホストは拒否 |
| T06 | 証明書 | 不正PEM、鍵不一致、未有効・期限切れ、SAN/発行者不一致、不正チェーン・EKUを拒否 |
| T07 | 整合性 | artifact改変、混在世代、過大応答、未知artifact、要求version不一致を拒否 |
| T08 | 冪等性 | 同一世代の再Pullで配置・reloadを繰り返さず、破損ローカルは見逃さない |
| T09 | 差分 | リーフ変更、チェーンのみ変更、世代更新を検出 |
| T10 | 配置 | 一時書き込み失敗、権限設定失敗ではcurrentを維持し、同時Pullを排他 |
| T11 | 復旧 | reload失敗・timeout・is-active失敗で旧世代を再反映し、復旧失敗も報告 |
| T12 | 中断 | 切り替え前後の停止と再起動で未完了処理を検出し、安全に復旧・停止 |
| T13 | dry-run/status | dry-runに副作用なし。statusに秘密鍵が含まれず実ファイル状態を反映 |
| T14 | 公開 | 不正な登録世代・保存ルート外参照を拒否し、並行取得で世代が混ざらない |
| T15 | DNS | 正引き・逆引き、serial境界、無変更、取得失敗、checkzone失敗、reload失敗を確認 |
| T16 | 発行 | SAN、鍵、期限、チェーン、serial、更新閾値、発行失敗時の旧世代維持を確認 |

Goコード導入後は`gofmt`、`go test ./...`、`go vet ./...`を実行する。並行処理の試験は対応環境で`go test -race ./...`を実行する。NSD/systemd連携はLinuxの隔離環境で検証し、モックだけで実環境対応済みとはしない。

## 証明書配布の受け入れシナリオ

1. テストCAからHTTPSサーバー用と配布用の証明書を作成する。
2. 配布用証明書を検証して保存し、クライアントに1証明書だけ割り当てる。
3. 正しいCA・資格情報・許可IPからPullし、配置権限と参照先を確認する。
4. 再Pullでサービス操作が起きないことを確認する。
5. 新世代へ更新し、サービスに新しい証明書が反映されたことをTLS接続で確認する。
6. 不正資格情報、別証明書名、許可外IPでは取得できないことを確認する。
7. 不正な証明書とreload失敗を注入し、旧世代維持・復旧と非ゼロ終了を確認する。
8. dry-run、status、ログに秘密情報が含まれないことを確認する。
9. Keycloak 1ホストで参照形式・reload/restart・復旧を検証する。本番変更は別途明示的な作業指示の範囲で行う。

隔離したKeycloak 26.8.2でPEMの参照、systemdによる再起動、切り戻しを確認した。運用環境のサービスユーザー、ユニット、鍵へのアクセス権限は別途確認する。keystoreを使う構成やreloadでの反映は未検証。

## ログ・状態

構造化ログにtimestamp、client_id、certificate_name、operation、result、error_categoryを含める。秘密鍵、トークン、パスフレーズ、認証ヘッダー、資格情報付き本文は記録しない。

配布APIは一覧・メタデータ・ダウンロードの結果をJSONログに記録する。`time` はイベント時刻で、クライアントIDは認証済みの値、証明書名は公開ストアに登録済みの値を使う。認証失敗ではクライアントIDを空にする。送信時の失敗には `transport` を記録する。

Pullは失敗箇所に応じて、在庫取得、計画、取得、配置、状態保存などを構造化ログで報告する。

同期ファイルには証明書別の成功世代、フィンガープリント、最終同期UTC時刻と、配置先のロック取得後に記録できた直近のエラーカテゴリーを保存する。配置状態は `status` が実ファイルを確認して判定する。トークン・秘密鍵を複製保存しない。状態ファイルは原子的に更新し、実ファイルとの不整合をstatusで隠さない。

## 運用

- HTTPSサーバーは専用ユーザーで実行し、保存領域とTLS鍵に必要な最小権限だけを付ける。
- Pullは所有者変更とsystemd操作が必要なローカル権限で実行し、設定を非特権ユーザーに書き換えさせない。
- 定期実行はsystemdのoneshot serviceとtimerを用いる。各timerの設定例をもとに、導入先の実行間隔とホスト間の分散を設定する。
- 配置先・状態・設定・信頼CAをバックアップし、復旧試験を行う。バックアップ内の鍵も秘密として保護する。
- 初回導入前に既存サービス設定と証明書を退避し、旧経路へ戻す手順を用意する。
- 資格情報漏えい時はクライアントを無効化し、配布APIが拒否することを確認する。定期読込を有効にした失効リストでも拒否できる。鍵も漏えいした可能性があれば証明書・鍵を交換する。[失効手順](../client-revocation.md)
- CA信頼設定の更新は配布証明書の更新と分離して計画する。失効・CA切り替えを通常Pullだけで解決できるとは扱わない。
- ディスク不足、証明書期限接近、同期失敗、復旧失敗を監視対象とする。監視ツール、通知先、しきい値は導入先で設定する。

## 導入時に残る確認

| ID | 実装・検証済みの範囲 | 導入時に確認すること |
| --- | --- | --- |
| D01 | ビルド要件と依存バージョンは [go.mod](../../go.mod) に記載。配置はLinux/systemdを対象 | 運用対象ディストリビューション・構成での動作 |
| D02 | 配布API、設定、トークンハッシュ、登録手順を実装 | 運用でのトークン配布・更新経路と権限 |
| D03 | 生成したテストCAで既存証明書の登録・配布・配置を確認 | 運用で使う証明書の形式、SAN、発行者・信頼CA |
| D04 | 隔離KeycloakでPEM配置、systemd再起動、切り戻しを確認 | 実際のユニット・ユーザーでの鍵アクセスと初回復旧 |
| D05 | systemdタイマー例とTLS照合のタイムアウト設定を提供 | 同期周期、ディスク・期限・同期失敗の監視閾値と通知先 |
| D06 | 提供CSVから生成した候補の構文検証とA・PTRの比較を実施済み | 実際のSheets接続、固定レコード・SOA・NS・TTLの照合、管理ゾーンの入れ替え |
| D07 | テスト用中間CAによる発行、暗号化PEM、更新タイマーを検証済み | 運用と同じ鍵保護方式での発行・配布、更新閾値と復旧 |
| D08 | 相互TLSとクライアント失効リストを実装済み | 運用での資格情報の更新・失効確認。プロキシ経由の信頼IPは構成を採用する場合に設計 |

隔離環境で確認した範囲は[引き継ぎメモ](../HANDOFF.md)、実際の移行に使う確認手順は[リリースと運用受け入れ](../release-and-acceptance.md)を参照する。
