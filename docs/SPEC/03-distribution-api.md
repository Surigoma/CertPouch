# 証明書配布API仕様

## 要件

- HTTPSのバージョン付きAPIとし、認証、送信元IP制限、証明書名ごとの認可を行う。
- IPは暗号学的な主体識別の代わりにしない。
- 接続元IPが台帳または静的設定で許可された証明書だけを配布する。
- CA秘密鍵は一切配布しない。
- メタデータには、名前、SHA-256 fingerprint、NotBefore/NotAfter、Subject、SAN、Issuer、versionを含める。
- ダウンロードでは、チェーンと秘密鍵を明確に区別する。

## HTTP共通契約

**TLSと認証**

- TLSの最小バージョンは1.2。クライアントはホスト名とCAを検証し、検証を無効化しない。
- 認証には `Authorization: Bearer <token>` と `X-CertPouch-Client-ID` を使う。資格情報をURLへ渡さない。
- health以外のすべてのAPIで、認証とIP制限を必須にする。メタデータも公開しない。
- クライアントIDで設定を選び、enabledとトークンハッシュを検証する。ハッシュは定数時間で比較する。
- リダイレクトには追従せず失敗とする。資格情報を別のoriginへ転送しない。

**接続元IPと認可**

- IPはTCP接続元から判定し、IPv4-mapped IPv6を正規化する。
- `Forwarded` や `X-Forwarded-For` を信頼しない。配布サーバーへの直接接続を前提とする。
- DNS台帳モードでは、証明書の論理名に対応するIPと、そのクライアントの例外設定にあるホストのIPから、接続元に許可する証明書を決める。
- 静的モードでは、クライアントの許可IPと証明書割り当てを使う。

**形式と制限**

- JSONはUTF-8、日時はUTCのRFC 3339、fingerprintとSHA-256は小文字16進64桁とする。
- すべての応答に `Cache-Control: no-store` を付け、秘密鍵をキャッシュさせない。
- タイムアウトは、クライアント要求全体が60秒、サーバーのReadHeaderTimeoutが5秒、WriteTimeoutが60秒。
- 1つのダウンロード応答の上限は4 MiB（JSONエンコード後）とする。クライアントもストリーム読み取りに上限を設ける。
- HTTP要求が失敗するとPullは非ゼロ終了する。定期実行では次回のtimerで再試行される。

## エンドポイント

| GETパス | 成功 | 内容 |
| --- | --- | --- |
| `/api/v1/health` | 200 | `{"status":"ok"}` のみ。秘密・在庫を含めない |
| `/api/v1/certificates` | 200 | 許可済み証明書のメタデータを `certificates` 配列で返す |
| `/api/v1/certificates/{name}/metadata` | 200 | 現在公開中の世代のメタデータ |
| `/api/v1/certificates/{name}/download?version={version}` | 200 | 指定した不変世代の一式 |

**パラメーター**

- downloadでは `version` を必須にする。
- URLには非秘密の識別子だけを含める。
- name・versionはデコード後に検証し、パス区切り、二重デコード、ディレクトリトラバーサルを拒否する。

**一覧**

- 名前の昇順で返す。
- 権限があっても、未公開の証明書は含めない。
- 空の一覧は正常な200とする。
- 許可された在庫をすべて返す。クライアントはローカル設定に列挙した対象だけを処理する。
- 設定済みの対象が一覧に存在しなければ、Pullは失敗する。

### メタデータ例

`<...>` は型を説明するプレースホルダーで、実際の値ではない。

```json
{
  "name": "web.example.internal",
  "version": "<opaque-version-id>",
  "fingerprint": "<64-lowercase-hex>",
  "not_before": "2026-11-01T00:00:00Z",
  "not_after": "2027-02-01T00:00:00Z",
  "subject": "CN=web.example.internal",
  "dns_sans": ["web.example.internal"],
  "ip_sans": [],
  "issuer": "CN=Example Intermediate CA",
  "artifact_sha256": {
    "certificate.pem": "<64-lowercase-hex>",
    "chain.pem": "<64-lowercase-hex>",
    "private-key.pem": "<64-lowercase-hex>"
  }
}
```

| artifact | 内容 |
| --- | --- |
| `certificate.pem` | リーフ証明書のみ |
| `chain.pem` | 直接発行した中間CAから上位の中間CAの順。ルートは含めない。ルートが直接署名した場合は空でよい |
| `private-key.pem` | リーフに対応する秘密鍵 |

### ダウンロード形式

ダウンロードは、メタデータとPEM文字列をJSONで返す。実応答の `metadata` は前項のすべてのフィールドを含む。

```json
{
  "metadata": { "name": "web.example.internal", "version": "<opaque-version-id>" },
  "artifacts": {
    "certificate.pem": "<PEM string>",
    "chain.pem": "<PEM string>",
    "private-key.pem": "<PEM string>"
  }
}
```

**クライアントの照合**

- artifactのハッシュ対象は、JSONデコード後のPEM文字列のUTF-8バイト列とする。改行は正規化せずに照合する。
- 期待した3キー以外は拒否する。
- 応答のname・versionを要求と照合する。取得済みのメタデータやハッシュと食い違う場合は配置しない。

**サーバーの一貫性**

- 1つの要求につき1つの不変世代を読む。途中で公開世代が変わっても、異なる世代の鍵と証明書を混ぜない。
- 指定世代が削除済みなら409で終了する。クライアントは次回のPullでメタデータから取り直す。

ハッシュは整合性検査であり、配布サーバーの侵害に対する独立した署名保証ではない。TLSと、ローカルのCA・SAN・発行者検証を併用する。

## エラー契約

| HTTP | 条件 | code |
| --- | --- | --- |
| 400 | 名前・version・入力形式の不正 | `invalid_request` |
| 400 | HTTPS以外の要求がハンドラーへ届いた | `https_required` |
| 401 | 認証の欠落、不正トークン、無効・未知のID、静的モードでの接続元IP拒否 | `unauthorized` |
| 404 | 証明書が存在しない、または接続元に取得の許可がない | `not_found` |
| 405 | GET以外 | `method_not_allowed` |
| 409 | 要求した世代を取得できない | `version_unavailable` |
| 503 | healthで、公開ストアの定期読み込みの失敗、台帳の読み込みの失敗、または設定した台帳期限の超過を検知した | `unavailable` |

- 応答は `{"error":{"code":"...","message":"..."}}` とし、パス、秘密情報、内部スタックを含めない。
- 認可前に、証明書の存在を判別できる応答を返さない。

### 公開ストアの読み込み

- 起動時に公開ストアを読み込む。
- 定期読み込み中に検証が失敗すると、healthは503を返し、配布APIは最後に検証済みの在庫を保持する。次に検証が成功すると200に戻る。
- 期限切れの世代は、有効期間内の最終時点で鍵・発行者・チェーン・SAN・EKUを照合する。照合に通った世代は警告を記録して配布対象から外し、ほかの世代の読み込みを続ける。
- 期限切れ以外の検証エラーは、上記の読み込み失敗として扱う。
- 新しく登録する世代には、現在時刻での検証を適用する。

### DNS台帳モードの認可

- 有効なトークンを持つ接続元に許可された証明書がない場合、一覧は200と空配列を返す。個別のメタデータ取得とダウンロードは404とする。
- `distribution.refresh_interval`（既定5秒）ごとに、新しい台帳の認可を反映する。
- 台帳の再読み込みに失敗した場合は、正常な台帳を読み込むまで認証を停止し、401を返す。
- `inventory.max_age` を設定した場合は、取得記録に基づく台帳の有効期限を新規リクエストごとに確認し、期限切れは401とする。

### 資格情報の変更と失効

- 資格情報の変更は、設定の再起動以後の新規要求に適用する。
- 失効リストを設定している場合は、定期更新でクライアントIDやmTLS証明書を拒否できる。リストを読めない場合は、正しいリストを読み込むまで配布認証を停止する。[失効手順](../client-revocation.md)
- 既に取得された秘密鍵は回収できない。必要に応じて鍵と証明書を交換する。
- mTLSを有効にすると、すべてのHTTPS接続でクライアント証明書の検証が必要になる。配布操作では、リーフのフィンガープリントをクライアントIDに結び付ける。IP判定には引き続き直接のTCP接続元を使う。[mTLSの設定](../mtls.md)
