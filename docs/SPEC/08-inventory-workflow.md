# 台帳からDNS・証明書を同期する目標仕様

[全体仕様の目標スコープ](../../SPEC.md#target-scope)を詳細化する。この章は実装の目標を定める。現在利用できるコマンドは[構成とCLI](01-scope-architecture.md)を参照する。

## 台帳と設定

日常の登録項目はホスト名、IP、任意の別名。管理者は通常のホスト追加時に発行フラグを記入したり、証明書ごとのYAML設定を追加したりする必要がない。サーバー側の同期・NSD・共通発行方針は `server.yaml`、受け取り側の接続先・取得対象・任意の配置後操作は `client.yaml` で管理する。既存CAを使用し、CA秘密鍵は発行処理だけが読み取れるようにする。

## 同期順序

1. 設定可能な間隔でSheetsを読み取り、台帳を検証する。通常時は数分程度の反映を目安とする。APIの割り当てを考慮し、制限応答や一時障害時は再試行間隔を延ばす。
2. 検証済みの台帳からDNS候補を生成し、NSDへの反映を確認する。取得・検証・反映に失敗した場合、その候補を証明書の発行・更新・取得停止の基準にしない。
3. DNSへの反映を確認できた台帳を基準に、名前ごとの証明書を発行・更新し、検証後に配布対象とする。DNSに変更がない同期でも、共通方針に基づいて期限を確認する。

Webhookは、将来同じ同期処理を早めに起動する入口とする。初期スコープの同期起点は定期ポーリングとする。

## 名前ごとの発行と配布

たとえば `web01.example.internal` と別名 `portal.example.internal` が同じIPを指す場合も、名前ごとに独立した証明書と秘密鍵を発行する。これにより、利用サービスは必要な名前の証明書だけを取得できる。

台帳への登録は発行対象を決める。HTTPSでの取得にはクライアント認証、接続元IP認可、要求された名前への取得権限が必要。受け取り側は配置後のサービス操作やローカルコマンドを任意に設定できる。

## 削除時の扱い

台帳から名前が消えた場合は、NSDで削除が反映されたことを確認してから、その名前の新規取得と自動更新を停止する。受け取り済みの証明書は有効期限まで使用できる。鍵漏えいなどで即時に対応する操作は、台帳同期による削除と分ける。

## 実装時の受け入れ条件

- 1行の追加でDNSにホスト名と別名が反映され、個別YAMLの編集なしで、別々の鍵を持つ証明書を取得できる。
- 同じIPを共有していても、認証されていないクライアントや要求名への権限を持たないクライアントは取得できない。
- Sheets取得失敗やNSD反映失敗を、台帳からの削除や反映成功として扱わない。
- 別名だけを削除すると、NSD反映後にその別名の新規取得と更新が止まり、元のホスト名は引き続き取得・更新できる。

## 現行実装との差

現行はSheets取得・候補生成、明示的なNSD反映、設定済みの証明書発行・更新、認証付きPullを提供する。台帳だけから発行対象を決める処理、NSD反映後の自動発行・更新、台帳削除後の自動停止は目標仕様。現在の操作例は[利用シーン別の操作例](../user-flows.md)を参照する。
