# 台帳からDNS・証明書を同期する目標仕様

この章は、[全体仕様の目標スコープ](../../SPEC.md#target-scope)を詳しく定める実装目標である。現在利用できるコマンドは[構成とCLI](01-scope-architecture.md)、現行との差は[末尾](#現行実装との差)を参照する。

## 台帳と設定

- 日常の登録項目は、ホスト名、IP、任意の別名だけとする。
- 通常のホスト追加で、発行フラグの記入や証明書ごとのYAML設定を求めない。
- サーバー側の同期・NSD・共通の発行方針は `server.yaml` で管理する。
- 受け取り側の接続先・取得対象・任意の配置後操作は `client.yaml` で管理する。
- 既存CAを使い、CA秘密鍵は発行処理だけが読み取れるようにする。

## 起動時のゾーン準備

| 変更 | 反映方法 |
| --- | --- |
| IPレンジの追加・変更 | 管理者がレンジ設定を編集し、CertPouchを再起動する。起動時に、管理対象レンジに対応するNSDのゾーンを準備する |
| 登録済みレンジ内のホストの追加・変更・削除 | 稼働中の定期同期で、準備済みゾーン内のレコードを更新する。再起動は不要 |

## 同期順序

`inventory.sheets.ranges` に、同じスプレッドシート内のA1形式の範囲を1件以上指定する。別のタブや同じタブ内の別範囲をまとめて読み取り、1つの台帳として検証する。

```yaml
inventory:
  sheets:
    spreadsheet_id: "REPLACE_WITH_ID"
    ranges:
      - "'Servers'!A2:G256"
      - "'Containers'!A2:G128"
    credentials_file: "/etc/certpouch/secrets/sheets.json"
  poll_interval: 3m
```

1. **取得:** 設定した間隔でSheetsを読み取り、台帳を検証する。通常は数分程度での反映を目安とする。APIの割り当てを考慮し、制限応答や一時障害では再試行の間隔を延ばす。
2. **DNS反映:** 検証済みの台帳からDNS候補を生成し、NSDへの反映を確認する。取得・検証・反映のいずれかに失敗した候補は、証明書の発行・更新・取得停止の基準にしない。
3. **証明書:** DNSへの反映を確認できた台帳を基準に、名前ごとの証明書を発行・更新し、検証後に配布対象とする。DNSに変更がない同期でも、共通方針に基づいて期限を確認する。

DNS反映後に証明書の発行だけが失敗した場合は、反映済みのDNSを維持する。その名前の発行は、DNSに差分がなくても次回の定期同期で再試行する。

### 台帳の扱い

- 正常に取得・検証した台帳は、削除・置換の件数に上限を設けずに同期する。
- 応答に含まれる指定範囲が空なら、その範囲の登録を削除したものとして扱う。
- Sheets APIの失敗や、指定範囲の応答欠落は、同期失敗として扱う。
- Webhookは、将来同じ同期処理を早めに起動する入口とする。初期スコープの同期起点は定期ポーリングとする。

### 現行の自動同期の動作

1. 取得した台帳と取得記録を一時ファイルへ保存してから、NSDを更新する。
2. 反映を確認した後に台帳を公開し、その台帳から発行対象を求める。
3. 配布サーバーは、同じ台帳の読み込み結果から公開一覧と認可を更新する。

- NSDとファイルシステムの切り替えは別の操作である。NSD反映後にキャッシュの保存が失敗した場合は、次回の同期で再試行される。
- 配布サーバーは、定期読み込みに起動時の設定、資格情報、信頼CAを使う。
- 台帳の鮮度を検証する読み込みは、台帳本体と取得記録の置き換えの完了を待つ。破損や保存途中の異常終了で両者が食い違った場合は、一致する組を次に取得できるまで配布を停止する。

## 名前ごとの発行と配布

たとえば `web01.example.internal` と別名 `portal.example.internal` が同じIPを指す場合も、名前ごとに独立した証明書と秘密鍵を発行する。利用サービスは、必要な名前の証明書だけを取得できる。

- 台帳への登録が発行対象を決める。
- HTTPSでの取得には、どのモードでもクライアント認証が必要である。
- 受け取り側は、配置後のサービス操作やローカルコマンドを任意に設定できる。

### クライアントごとの取得制限

サーバー設定で、クライアントごとに取得制限を選ぶ。以下は目標仕様のモードである。現行の設定キーは[設定仕様](02-configuration.md)を参照する。

| モード | 認証済みクライアントが取得できる範囲 |
| --- | --- |
| 台帳IP一致（既定） | 要求名に対応する台帳IPと、接続元IPが一致する名前 |
| 名前の許可リスト | 許可リストに明示した名前 |
| 台帳IP一致と名前の許可リスト | 両方の条件を満たす名前 |
| 追加制限なし（明示選択） | 現在配布中のすべての名前 |

- モードを省略した場合は、台帳IP一致を適用する。
- 不正なモードや不完全な許可リストは設定エラーとする。
- 制限は、一覧、メタデータ、ダウンロードのすべてに適用する。
- 配布を停止した名前は、追加制限なしを含むすべてのモードで新規取得の対象外とする。

## 削除時の扱い

- 台帳から名前が消えた場合は、NSDで削除が反映されたことを確認してから、その名前の新規取得と自動更新を停止する。
- 受け取り済みの証明書は、有効期限まで使用できる。
- 鍵漏えいなどで即時に対応する操作は、台帳同期による削除とは分ける。
- 台帳から発行対象を決める構成では、削除された証明書名をキーに持つ例外許可と、削除された例外ホストからの許可を無効化する。同じ設定内の有効な名前は引き続き処理する。
- 例外に記述した名前の形式と、モードとの組み合わせは、設定の読み込み時に検証する。

## 実装時の受け入れ条件

**ゾーンと同期**

- IPレンジを設定に追加して再起動すると、対応するゾーンが準備される。その後、登録済みレンジ内のレコードは再起動せずに更新できる。
- DNS反映後に証明書の発行だけが失敗した場合は、配信中のDNSを維持し、次回の同期でその名前の発行を再試行する。
- 正常な台帳に多数の削除・置換があっても、件数だけを理由に同期を止めない。
- Sheetsの取得失敗やNSDの反映失敗を、台帳からの削除や反映成功として扱わない。

**発行と取得**

- 1行の追加で、DNSにホスト名と別名が反映され、個別のYAML編集なしで、別々の鍵を持つ証明書を取得できる。
- 同じIPを共有していても、認証されていないクライアントや、要求名への権限を持たないクライアントは取得できない。
- 台帳IP一致と許可リストを併用すると、片方だけを満たす要求は取得できない。追加制限なしを明示した場合も、未認証の要求は拒否する。

**削除**

- 別名だけを削除すると、NSD反映後にその別名の新規取得と更新が止まり、元のホスト名は引き続き取得・更新できる。

## 現行実装との差

- `pipeline --watch` で定期同期できる。
- [設定例](../../configs/server.example.yaml)では、専用のNSD includeを使った起動時のゾーン準備と、台帳ベースの発行を設定できる。
- 配布対象からの除外は、配布サーバーの定期読み直しで反映する。

現在の手順は[DNS同期](../dns-sync.md)と[証明書更新](../certificate-renewal.md)を参照する。
