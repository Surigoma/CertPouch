# クライアントの失効

資格情報の漏えい時などに、特定のクライアントの取得を配布サーバーの再起動なしで停止する方法です。

## 設定する

1. 配布サーバーの `server.yaml` で、`distribution.revocation_file` に失効リストの絶対パスを設定します。

   ```yaml
   distribution:
     revocation_file: "/etc/certpouch/revocations.yaml"
     revocation_refresh: "5s"
   ```

2. 設定を追加したら、配布サーバーを再起動します。

- 稼働中のサーバーは、リストを既定で5秒ごとに読み直します。
- 間隔は `distribution.revocation_refresh` で、1秒以上の期間に変更できます。

## 失効リストを書く

[失効リスト例](../configs/revocations.example.yaml)のように、両方の配列を明示します。

```yaml
client_ids: ["web-server-01"]
client_certificate_sha256: []
```

| キー | 指定する値 |
| --- | --- |
| `client_ids` | 停止したいクライアントID |
| `client_certificate_sha256` | 停止したいmTLSリーフ証明書のSHA-256。表記は[mTLSの設定](mtls.md)と同じ小文字16進64桁 |

すべての失効を解除する場合は、両方の配列を明示的に空にします。

## 更新するときの注意

- 管理者が別ファイルで編集し、同じファイルシステム上で名前を置き換えて反映します。
- 配布サーバーには読み取り権限だけを与え、配布サーバーや他のユーザーに編集権限を付けないでください。
- 不完全なファイルを読み込んだ場合は、正しいリストを読み込むまで配布認証を停止します。
- ファイルを削除した場合も、認証は停止します。

## 失効の効果と限界

- 反映後に始まる取得要求は、接続が確立済みでも401になります。
- すでに応答を開始したダウンロードや、端末が過去に取得した秘密鍵は回収できません。
- 漏えいしたトークンや証明書を交換してから、失効を解除してください。
- リストへの追加・削除によって、既存のクライアント認証やIP認可に許可が加わることはありません。
