# クライアントの失効

漏えい時などに取得を停止するには、配布サーバーの `server.revocation_file` に失効リストの絶対パスを設定する。設定を追加したら配布サーバーを再起動する。稼働中のサーバーは、指定されたリストを既定で5秒ごとに読み直す。`server.revocation_refresh` で1秒以上の期間に変更できる。

```yaml
server:
  revocation_file: "/etc/certpouch/revocations.yaml"
  revocation_refresh: "5s"
```

[失効リスト例](../configs/revocations.example.yaml)には両方の配列を明示する。停止したいクライアントID、またはmTLSリーフ証明書のSHA-256を指定する。フィンガープリントの表記は [mTLSの設定](mtls.md) と同じ小文字16進64桁。

```yaml
client_ids: ["web-server-01"]
client_certificate_sha256: []
```

管理者が別ファイルに編集し、同じファイルシステム上で名前を置き換えて反映する。配布サーバーには読み取り権限を与え、配布サーバーや他のユーザーに編集権限を付けない。不完全なファイルを読み込んだ場合は、正しいリストを読み込むまで配布認証を停止する。ファイルを削除しても認証は停止する。すべての失効を解除する場合は、両方の配列を明示的に空にする。

反映後に始まる取得要求は、接続確立済みの場合も401になる。すでに応答を開始したダウンロードや、端末が過去に取得した秘密鍵は回収できない。漏えいしたトークンや証明書を交換してから、失効を解除する。リストへの追加・削除は既存のクライアント認証やIP認可に許可を追加しない。
